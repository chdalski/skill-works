# Contrarian Checklist

The checks the advisor makes on a brief before any procedure
is designed. Each item asks for a reason not to build the
skill as the brief describes it; for a brief that changes a
skill (`change: yes`), read "the skill" as "the change".
Answer every item, in this order.

## 1 Need

Is a skill needed at all? Look at the problem the brief names
and at how it is done today. No skill is needed when a line
in the project's instructions, a script, or a command does it
as well, or when the brief does not show that the problem
exists and recurs.

## 2 Existing skills

Does an existing skill, from the list you were given or in
the project, do most of it? Name the skill and the part it
already covers; extending that skill may serve instead of a
new one.

## 3 Size and place

Is the skill a phase or a sub-skill of another skill rather
than a skill of its own? Or is it several skills, each with
its own trigger and result?

## 4 Non-goals

Does the brief say what the skill does not do? Name a nearby
task that a user would expect the skill to do and that the
brief neither includes nor excludes.

## 5 Alternatives

Which alternative did the brief not weigh? Read the section
Alternatives weighed, and name one that would solve the
problem with less: another form, another target, or no skill.

## Report

For each item, in order:

    ## <number> <item>
    <one or two sentences: your answer>
    - objection: <the reason against> — rests on: <a place in
      the brief, a skill, or a file> — answered by: <what the
      brief would need to say or change>

An item without a reason against has the line
"- no objection". An objection repeated from an earlier round
ends with "(repeated)".

The last line of the report is the summary line:

    Summary: <build as briefed | build in another form | not needed>; main objections: <the 2–3 that weigh most, each as its item number and a few words, or none>

The report is complete when it answers every item and ends
with the summary line.
